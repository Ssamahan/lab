# Protected NRL reports

Historical NRL reports are kept separately from the shared samples register in the private Supabase project. Apply `supabase/private-referral-results.sql` only to that project, after its private-names schema. Only accounts on the private-names allowlist can read them; each read is recorded server-side. Adding an app-level role alone does not grant access. The current authorized account can open **Referred samples → Private names**, sign in to the private project, then select **Protected NRL results**. The view requires a network connection and clears when the private session ends. It is not included in ordinary sample exports, shared sync, backups or stock consumption.

This is a read-only historical view, not a replacement for the existing operational sample register. Existing sample records, their shared sync and historical copies have not been migrated or made private by this feature. Do not enter patient details into the public register or its notes. A browser or device used to view results can still expose them to someone with access to that device; this feature is not end-to-end encryption.

Import only a verified laboratory report into `private.referral_result_reports`, using its NRL sample ID as the unique key and preserving a source reference. Keep report data and credentials out of the repository. Reconcile source documents and existing samples manually; do not infer collection or referral dates, change stock, overwrite existing records, or treat a scanned image as readable without verifying it. The database deliberately exposes no client write endpoint. Backups, account administration, clinical review and wider authorized staff access need their own procedures; the private project is hosted in the UK.
