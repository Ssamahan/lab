Put the lab register in the sky ☁️

A very slow, very clear guide to Supabase. No computer words you don't already know. About 15 minutes, once, and then every phone and PC in the lab sees the same register.

First, the three words

What we are actually doing

  • The app is already on your PC. It keeps everything in the browser — that is why it works with no internet.
  • Supabase is a computer in the sky that never sleeps. We will keep one copy of the register there.
  • When a phone and a PC both look at that copy, they see the same work. That is all "sync" means.
Nothing about the app changes. It still works with no internet. The sky copy is only a second copy.
Before you start

You need four things

Part 1

Make your own Supabase project

  1. Go to supabase.com and press Start your project.
  2. Sign in with your email (or GitHub if you have it). It is free — you do not need a card.
  3. Press New project.
  4. Fill the form like this:
    • Name: ruli-lab
    • Database password: type something long, then write it down somewhere safe. Supabase will never show it again.
    • Region: choose the closest to Rwanda — Europe (Frankfurt) or South Africa if you see it.
  5. Press Create new project and wait about 2 minutes. A green Active word means it is ready.
Think of a project as one empty cupboard in the sky. We are about to put one shelf and one box inside it.
Part 2

Copy the two magic keys

  1. In the left menu (the little icons) go to Project Settings ⚙️.
  2. Open API (or API Keys).
  3. Copy Project URL — it looks like https://abcdefgh.supabase.co. Copy only that, with nothing after .supabase.co — no /rest/v1.
  4. On the same page open API Keys. Find the box called Publishable key and copy the key inside it — it starts with sb_publishable_.
    (An older project may show a key called anon instead, starting with eyJ. That one still works — copy it.)
Paste both into a note on your computer for a minute. Part 5 asks for them.
Never copy the Secret keys (sb_secret_…) or the old service_role key. That is the master key to the whole cupboard: it skips every lock. Only the Publishable key belongs in a browser — the app will refuse the secret one if you paste it by mistake.
Part 3

Build the shelf (one copy‑paste)

  1. In the left menu open SQL Editor.
  2. Press New query.
  3. Delete anything in the box, then paste all of the code below.
  4. Press Run (or Ctrl/⌘ + Enter).
  5. You should see “Success. No rows returned.” That is a good thing — it means the shelf was built.
-- ============================================================================
-- LAB SYSTEMS · RULI DISTRICT HOSPITAL — Supabase schema
-- Run this once in the Supabase SQL editor (Dashboard → SQL → New query).
-- ----------------------------------------------------------------------------
-- One row holds one laboratory register. The console is offline-first: the whole
-- register lives in the browser and this table is the shared copy that lets a
-- phone and a PC see the same work.
--
-- Security model
--   * Row level security is on, with NO anonymous policies.
--   * Every signed-in account of the laboratory project may read and write the
--     single 'ruli-dh' register. That is deliberate: the app has its own role
--     model, and Supabase is only the transport. If you later need per-user
--     isolation, replace the two policies below with a `lab_members` join table.
--   * Use the ANON key in the app. Never put the service_role key in a browser.
-- ============================================================================

create extension if not exists pgcrypto;

create table if not exists public.lab_registers (
  id          text primary key,
  data        jsonb        not null,
  revision    bigint       not null default 1,
  client_id   text,
  updated_at  timestamptz  not null default now(),
  updated_by  text
);

comment on table public.lab_registers is 'Whole-register documents for Lab Systems (one row per laboratory).';
comment on column public.lab_registers.revision is 'Incremented by the server on every write; the client uses it to detect a conflict.';

create index if not exists lab_registers_updated_at_idx on public.lab_registers (updated_at desc);

-- Keep updated_at honest even if a client forgets to send it.
create or replace function public.touch_lab_register()
returns trigger language plpgsql as $$
begin
  new.updated_at = now();
  return new;
end $$;

drop trigger if exists lab_registers_touch on public.lab_registers;
create trigger lab_registers_touch before insert or update on public.lab_registers
for each row execute function public.touch_lab_register();

-- ---------------------------------------------------------------- RLS --------
alter table public.lab_registers enable row level security;

drop policy if exists "lab register read"  on public.lab_registers;
drop policy if exists "lab register write" on public.lab_registers;

create policy "lab register read" on public.lab_registers
  for select to authenticated using (true);

create policy "lab register write" on public.lab_registers
  for insert to authenticated with check (true);

create policy "lab register update" on public.lab_registers
  for update to authenticated using (true) with check (true);

-- If the laboratory would rather use a single shared passphrase than Supabase
-- Auth accounts, enable "Allow anonymous sign-ins" and swap `authenticated` for
-- `anon` in the three policies above — but understand that anyone with the anon
-- key then has the register. The default (authenticated) is the safer one.

-- ---------------------------------------------------------------- seed -------
-- Nothing is inserted here: the first device to press "Push to cloud" creates
-- the row. To pre-seed from a device export, paste the JSON:
-- insert into public.lab_registers (id, data, client_id, updated_by)
-- values ('ruli-dh', '<paste export here>'::jsonb, 'setup', 'kelvin');
What did that do? It made one table called lab_registers — one row will hold the whole laboratory register — and locked it so only signed‑in people on your project can touch it.
Part 4

Make your login

Important: the way you signed into supabase.com — GitHub, Google, email — has nothing to do with this. That login only opens the dashboard. The app needs a user of your project, and you make it yourself in two clicks. Yes, even if you used GitHub.

Pick one of these two ways:

Using more than one device? Use the same way on every device. A phone on Way B and a PC on Way A both end up in the same project, but a device holding a wrong password fails while the other works. If the second device refuses, the app offers a one-press Use an anonymous session button so it matches the first one.

Way A — a project user (recommended)

  1. Left menu → Authentication.
  2. Open Users, then press Add user → Create new user.
  3. Email: something that looks real, for example lab@rulidh.rw. (It does not have to be able to receive mail.)
  4. Password: long, written down.
  5. Tick Auto confirm user — otherwise the account waits for an email nobody will send.
  6. Press Create user. Done: the app will sign in with this, not with your GitHub account.

Way B — no password at all (anonymous session)

  1. Left menu → Authentication, then the Sign In / Providers tab.
  2. Scroll the list of providers until you find the switch Allow anonymous sign-ins and turn it on. It is not inside the Email provider — it sits at the top of that same list as its own switch.
  3. In the app, tick Anonymous session, leave the email and password empty, and press Test connection. If you had already pressed it, press again: the app re-reads the switches every time you test.
The app can take you there. Once your project address is saved, the Cloud sync card shows Open Auth providers, Open Auth users and Open SQL editor — those three links land on the exact page for your project, because the address itself contains the project reference.
“I can't see Auto Confirm User.” That switch only appears while email confirmations are on. If your project already has them off, every user is confirmed the moment you create them — nothing to tick, nothing to do.

To check or change it: Authentication → Sign In / Providers → Email. If Confirm email is off, you are done. If it is on and you still see no switch, create the user anyway: the row appears in the list, and you can press ⋯ → Confirm email on that user afterwards. The app's new Check setup button tells you which case you are in.
Way B is quicker, but anyone who finds your project address and publishable key could also open a session. The register holds patient names. Use Way B to get running today, then move to Way A before the lab depends on it.
Part 5

Tell the app about it

  1. In Lab Systems go to Staff & settings → Data tab.
  2. Find the Cloud sync card on the right.
  3. Paste, in order:
    • Supabase project URL → the address from Part 2
    • API key · publishable → the sb_publishable_… key from Part 2
    • Project user · email → the email from Part 4, Way A
    • Project user · password → the password from Part 4, Way A
      — or tick Anonymous session and leave both empty (Way B)
  4. Leave Mode on Two‑way · pull then push.
  5. Press Test connection. You want the green message “Connected to Supabase — ready for the first push”.
  6. Press Save. The app publishes the register by itself. The pill at the top of the card turns to Synced just now.
If it says “the table is missing”, Part 3 did not finish — run that code again. If it says “Supabase said no (401)”, the email/password from Part 4 is wrong, that user was never confirmed, or the login is empty — the publishable key on its own is only a stranger at the door.
Part 6

Do the same on your phone

  1. Open the same app address on the phone and sign in as yourself.
  2. Go to the same Cloud sync card and paste the same four things.
  3. Press Test connection, then Save.
  4. The phone says “Register updated from the shared cloud”. That is the moment your two devices become one.
Part 7

The magic test 🎩

  1. On the PC, change one shift in the working plan.
  2. Wait about one second, then look at the phone.
  3. The same change should be there.
How fast is it? A change leaves the device about 0.7 seconds after you make it, and the other device checks for news every 2.5 seconds — so in practice the phone shows the PC's change in about one to three seconds, with nothing pressed. The header pill says Live when this loop is running. It is in the Cloud sync card as Live sync if you ever want it off.
One honest limit. The register is one document, not a pile of rows. If two people change two different things at the very same second, the second device to save publishes its whole copy and the other copy is kept as a restore point — the app tells you on the card, and never silently throws it away. Keep one person editing the roster at a time; reading on as many devices as you like.
The app saves on the device first, always. The sky copy follows along when the internet allows it. Nothing you type is ever waiting for the internet to work.
Part 8 — the important one

Close the anonymous door before real patients

If you used Way B, syncing works — and that is worth enjoying. But understand exactly what is standing open:

  • An anonymous session is a real signed-in session to Supabase. The database cannot tell it apart from a person.
  • The publishable key is public by design — it says so on the Supabase page.
  • So while anonymous sign-ins are on, anyone who has your project address and that key could open a session and read, or overwrite, the whole register — patient names included.
The app will keep telling you this: Check setup adds a red row called Register privacy the moment the register holds patient names while anonymous sessions are on.

The ten-minute upgrade to a proper door

  1. Authentication → Users → Add user. Email lab@rulidh.rw, a long password, Auto Confirm User if it appears. Create.
  2. On each device: untick Anonymous session, type that email and password, press Test connection, then Save. The register stays exactly as it is — only the door changes.
  3. Authentication → Sign In / Providers → Allow anonymous sign-ins → off.
  4. Press Check setup on each device: everything should be green, and Register privacy should be gone.
  5. Optional, the strongest lock: in the SQL Editor, run the commented block at the bottom of supabase/schema.sql (marked hardening). It makes the database itself refuse anonymous sessions, even if the toggle is switched back on by mistake.
Do this before the first real patient record, not after. Nothing on the devices is lost by switching: the register lives on the device and in the cloud, and the route only decides who may open the door.
Part 9 — a new browser

Incognito, a new PC, a new phone

A private window, or any browser that has never been set up, starts from the app's built-in sample register. It cannot know your project address or key, so the work you typed on the PC is not there — the marks are not lost, they are simply in another browser.

  1. On the browser that already works: Staff & settings → Settings → Data & sync.
  2. Press Push everything now and accept. It publishes your whole register and shows the revision Supabase stored.
  3. Press Copy setup code. It is text that carries the address, the publishable key and the mode — never a password.
  4. In the new browser: sign in, open the same card, press Paste setup code, paste, Apply.
  5. Press Download the shared copy. Every sample, roster, leave record and PBF mark arrives; what was in the new browser is kept as a restore point.
Compare in that card shows the two copies side by side — samples, staff, PBF visits and PBF marks — so you can see whether the cloud really has what you typed. If that browser has never received the shared register, the app now refuses to publish its empty seed over it and says so.

Good habits

Three rules that keep the lab safe

  • The Secret keys (sb_secret_…) and the old service_role key never leave the Supabase website. Ever.
  • The login lives on the device where you typed it. Do not email it around.
  • Once a month, open Settings → Data & backup and press Export register. A copy in your own hand is worth more than any cloud.
